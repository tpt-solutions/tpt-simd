# Unsafe audit

Scope: every `unsafe fn`, `unsafe impl` and `unsafe { }` block under `tpt-simd*/src` (2026-10-17).
Run with the Miri pass in [todo.md](../todo.md) (Phase 8).

## Counts

| Item | Count |
|---|---|
| `unsafe fn` (including `pub(crate)` and private) | 71 |
| `unsafe { }` blocks | 287 |
| `pub unsafe fn` (public API) | 9 (gather 4, scatter 4, sparse 1) |

Every crate with `unsafe` is in the CI Miri job except `tpt-simd-interpolate`, whose single
`unsafe` block (`fma8`, the `_mm256_fmadd_ps` path) is compiled only with `avx` and `fma` enabled.
Miri does not enable those features, so the block is never built under Miri. Add the crate to the
CI list if the policy changes.

## Checks and results

1. **Every `unsafe` block has a `SAFETY:` comment within the six lines above it.** Result: 287 of 287.
2. **Every public `unsafe fn` has a `# Safety` doc section.** Result: 9 of 9. (One `pub(crate)`
   helper generated by a macro was flagged by a naive scan. It is not public API, and it has no
   `pub` visibility.)
3. **`#[target_feature]` functions are reached only when the feature is guaranteed.** Each
   target-feature function (AVX2, AVX-512F/BW, PCLMULQDQ, VPCLMULQDQ, AVX) is reached by one of:
   - a compile-time `cfg` that enables the same features (`cfg(all(target_feature = "avx512f"))`
     and similar, in `blas`, `convolve`, `compare`, `dot`, `permute`, `reduce`); or
   - a runtime check. `available()` in `search` and `text` uses `is_x86_feature_detected!("avx2")`
     and returns `false` under Miri. `wide_available()` in `hash` checks AVX2 and VPCLMULQDQ.
     `blas` uses `tpt_simd_core::dispatch::x86_avx2_fma()`.
   The `cfg!(target_feature = ...)` branches (used when `runtime-dispatch` is off) are constants
   at compile time, so they cannot select a path the build does not support.
4. **Callers of the `pub(crate)` kernels that document "requires `available()`" check it.** Every
   caller in `search` and `text` (AVX2 kernels) is guarded by `available()`, and so is each
   AVX-512 kernel call site.

## Findings

- No unsound call site was found under the checks above.
- No change was needed for this audit.

## Not covered

- Check 1 and check 2 test presence, not the content of the argument. A line-by-line proof of
  each of the 287 blocks was not done. The guard review in check 3 covers feature availability
  only.
- The intrinsic (x86 and NEON) code cannot run under Miri, so its memory accesses are checked by
  the tests on the host CPU and by reading, not by Miri.
- No runtime test runs on a CPU without AVX2 or AVX-512. The portable path for such CPUs is the
  `scalar-only` test run in CI.
