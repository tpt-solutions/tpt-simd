# ADR 0006: Scope decisions for 0.1

Status: **accepted** (2026-10-16, maintainer approval).

## Context

Phase 1 and the Phase 11 section of `todo.md` had open items that depended on policy calls
rather than on code. This records each decision, so the todo can point here instead of
keeping the question open.

## Decisions

1. **MSRV floor is 1.95.** `cargo msrv find` (cargo-msrv 0.19.3) reports 1.95.0 as the lowest
   passing toolchain. The CI `msrv` job keeps it there. The "stable-2" wording in the
   project decisions is replaced by "1.95, stable-3 when written". The floor changes only in
   a minor release, and the change goes in the CHANGELOG (`docs/release.md`).

2. **`nightly` stays a reserved no-op for 0.1.** Backend selection through
   `#![feature(portable_simd)]`, and tests that mirror `core::simd`, move to post-0.1. Enabling
   `portable_simd` would break stable `feature-powerset` CI, and a second backend would need its
   own maintenance.

3. **`tpt-simd-vector` stays `#![forbid(unsafe_code)]`.** Intrinsic fast paths live in the
   kernel crates (SSE2, AVX2, AVX-512 and NEON, each behind `cfg`), as they already do. The
   "core::arch fast paths for tpt-simd-vector" item is closed on that basis.

4. **Explicit SIMD for the Phase 11 crates is post-0.1.** Those crates keep
   `#![deny(unsafe_code)]`, and they run on autovectorised code for 0.1. This is the decision
   already stated in the Phase 11 section; the open boxes there are deferred, not forgotten.

5. **The complex multiply target (≥3× over scalar) is an accepted gap.** Against an
   autovectorised zip loop the speedup is about 1.0–1.1×. The crate's value for 0.1 is
   fused-FMA semantics and the portable API. Recorded here, as ADR 0005 does for other gaps.

6. **Core traits are frozen for 0.1.** The public traits are `SimdVector` and `SimdOps`
   (`tpt-simd-core`), and `SimdElement`, `MaskLane`, `SimdInt`, `SimdFloat` and `LaneCast`
   (`tpt-simd-vector`). Changing any of them after 0.1 is a breaking change. The review was a
   read of the trait list, not a second implementation pass.

7. **Crate-done for 0.1** is defined in [crate-done-audit.md](../crate-done-audit.md). It does
   not require `cargo-show-asm`; that is tracked separately in [asm-audit.md](../asm-audit.md).

8. **Vector-length CI runs the full matrix on every PR** (SVE 16/32/64/256 bytes; RVV VLEN
   128/256/512). Revisit this if PR turnaround becomes a problem; the fallback is two vector
   lengths on PRs and the full matrix nightly.

9. **The benchmark regression check is informational on PRs and blocking on master.** A PR
   regression is reported but does not fail the run. A master run compares against the previous
   master baseline and does fail on a regression. Shared runners are noisy, so this stays
   informational on PRs until several runs show the noise level.

10. **Phase 4 fallback items (decided 2026-10-16).**
    - *Per-lane libm in `tpt-simd-vector`* (`mul_add`, `sqrt`, `floor`, and the other
      float ops that call libm per lane): kept. Removing it needs `unsafe`, and point 3 keeps
      that crate safe. The fix goes in the kernel crate that needs the fused or lane op, as
      `tpt-simd-mul` and `tpt-simd-interpolate` already do with `cfg`-gated intrinsics.
    - *Float `Simd::min`/`max`*: fixed in `tpt-simd-vector` with comparisons that match libm
      bit for bit (including signed-zero ties), with no per-lane call and no `unsafe`.
    - *`mul_add_sub_f32`*: AVX2 path now uses one `vfmsubadd`.
    - *`shift_with_rounding_var_i32`*: AVX2 path, bit-identical to the scalar rule.
    - *`Fixed<i16>` multiply*: 32-bit lanes instead of 64-bit, bit-identical (the product
      fits in `i32`).
    - *Saturating `f32` to integer cast*: kept scalar. `from_f32` measured 0.7 to 1.0x, so a
      vector cast has nothing to gain (docs/benchmarks.md).
    - *Lanczos on non-finite input*: the SIMD and scalar paths may differ between NaN and
      ±inf. Both return a non-finite value, and that is the contract. The exact value is
      unspecified.

11. **Architecture coverage and Phase 11 SIMD (decided 2026-10-16, recommended option).**
    - *AVX-512 for every crate*: post-0.1. The crates with an AVX-512 path are listed in
      `todo.md` (Phase 8). The others use their AVX2 or portable path. Measured gains exist only
      where a kernel is wider than 8 lanes, so a blanket pass would add code without a
      measured benefit.
    - *NEON for every crate*: post-0.1 for `complex`, `horizontal`, `interpolate`, `window`,
      `math`, `rng` and `sparse`. These run their portable paths on aarch64. Adding NEON needs
      QEMU or aarch64 hardware to verify it, and neither is set up for this work. `gather` and
      `scatter` stay portable on aarch64 (item 10 of the Phase 8 decision).
    - *Explicit SIMD and asm audits for the Phase 11 crates*: post-0.1. Their crate-done gate
      (point 7 above) does not require asm, and they keep `#![deny(unsafe_code)]`
      (ADR 0006 item 4). Their proptests and benches exist and are the 0.1 gate.
